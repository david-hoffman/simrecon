# Intake

**Version 1.0.** Follow root AGENTS.md. This session defines architecture/tasks, not executable tests or product code. Use the package PROJECT/TASK templates and INTAKE-PROMPT. Reuse approved architecture, even under another filename. Resolve missing/materially inconsistent project decisions before product work. SIMrecon's approved functional Python/NumPy/SciPy architecture applies; legacy study material supplies no approved feature or test oracle.

Ask only material unresolved questions. Distinguish observed, proposed and approved behavior; settle numerical units, conventions and estimator meaning before tests. Test authors can derive justified tolerances from approved algorithm/precision information without inventing an accuracy requirement. For bugs separate reproduction, expectation and unverified cause; authorize an uncertain investigation as report-only.

Before formal test design, inherit the approved project coverage policy or resolve the missing owner choice under specification section 5.1. Behavior coverage and independent risk review always apply; the owner may additionally select line, statement, branch or combined targets. Record the choice/reason/actual authorization and each selected metric's tool/command, threshold, runtime/package/platform scope, aggregation, exclusions and reporting limits in PROJECT. Lines and statements are distinct metrics. Tasks reference that policy and identify relevant high-risk paths; settled choices need no repeated interview. Preserve installed gates until independently reviewed, owner-authorized policy migration and authorized infrastructure changes reconcile them. An unmet selected target blocks acceptance; unselected metrics are advisory.

Classify coverage findings under specification section 5.2 before commissioning corrections. State the missing approved outcome or concrete reachable risk, evidence and why current tests miss it. Route test gaps to their authorized test owner, unnecessary implementation to its author, new semantics to intake, and measurement defects to the authorized infrastructure owner. A bare uncovered branch supplies no new requirement. An irreducible selected-target conflict needs an explicit owner policy decision or remains blocked; classification grants no edit authority and resets no accounting.

Select mechanical, bounded or high risk by behavioral impact/uncertainty using specification section 4. Mixed work takes the highest route unless independently scoped. Policy documentation has human-requested scope and fresh policy review before activation. Define named test/fixture/infrastructure ownership for bounded workers; never loosen C by calling it bounded. Gate maintenance always gets independent review; new execution/security authority and data-loss behavior are high risk. A settled overwrite/truncation repair stays high risk even with conventional expectations. Record route/reason, permitted edits, checks, default full-local gate, model/effort/calibration status, diagnosed escalation triggers, cumulative attempts and any actual human-set limits. Any conditional CI-authoritative evaluation must be part of the human request and prove section 6 eligibility; high risk is excluded.

Create one contract or one slice plan with all contracts/dependencies/outcomes and any actual human-set limits. There is no default scenario count or execution budget. Map every distinct decision/outcome scenario. Equivalent values under the same decision are coverage examples. New rejection/interpretation/guarantee/boundary meaning is another scenario; do not hide it under a parameterized test. Inventory operation, invalid input, representation limits, operation-time failure, compatibility and documentation. Plan each baseline against full verification and the approved coverage policy; expose infeasible dependencies early. Splitting/redistribution preserves objective, dependencies, cumulative attempts and any explicit limits.

The human request authorizes its intended scope for every route. Record the actual instruction/revision and a concrete contract; proceed without a second approval of the record. Routine named role/check transitions, diagnosed in-scope repairs and fresh required reviews follow existing authorization. Ask only for missing material decisions, unclear/outside-request objectives or human-required external authority. No default review/repair quota, review window or exhausted-allowance stop applies. Recurring failures require concrete diagnosis and evidence before correction; continue within ownership, role boundaries and actual human-set limits, without an uncontrolled automatic retry loop. Silence supplies no missing decision; architecture supplies context, not a scientific feature request.

Prepare [PUBLIC-PACKET](../../../docs/agentic-software-delivery-v1.0/templates/PUBLIC-PACKET.md) for A/B and [CANDIDATE-PACKET](../../../docs/agentic-software-delivery-v1.0/templates/CANDIDATE-PACKET.md) for workers/final reviewers. Blind inputs exclude implementation/history/conversations, implementation-bearing state, coverage maps and existing lessons. Sanitize correction findings into approved public reproductions; dependency mapping comes only from tests/requirements. Shared fixtures/oracles expand review; new meaning returns here. Coordinator launches actual fresh native high-risk roles and fresh independent bounded/policy review sessions without author history. A role already launched performs its packet directly. Retain one Current state, cumulative attempts/spending, diagnosed corrections, actual limits or not set, and measured values or explicit unknowns. Fresh context or policy migration erases no charges; historical task records remain facts.
