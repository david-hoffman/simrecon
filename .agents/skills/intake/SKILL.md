# Intake

**Version 1.0.** Follow root AGENTS.md. This session defines architecture/tasks, not executable tests or product code. Use the package PROJECT/TASK templates and INTAKE-PROMPT. Reuse approved architecture, even under another filename. Resolve missing/materially inconsistent project decisions before product work. SIMrecon's approved functional Python/NumPy/SciPy architecture applies; legacy study material supplies no approved feature or test oracle.

Ask only material unresolved questions. Distinguish observed, proposed and approved behavior; settle numerical units, conventions and estimator meaning before tests. Test authors can derive justified tolerances from approved algorithm/precision information without inventing an accuracy requirement. For bugs separate reproduction, expectation and unverified cause; authorize an uncertain investigation as report-only.

Select mechanical, bounded or high risk by behavioral impact/uncertainty using specification section 4. Mixed work takes the highest route unless independently scoped. Policy documentation has explicit approval and fresh policy review before activation. Define named test/fixture/infrastructure ownership for bounded workers; never loosen C by calling it bounded. Gate maintenance always gets independent review; new execution/security authority and data-loss behavior are high risk. A settled overwrite/truncation repair stays high risk even with conventional expectations. Record route/reason, permitted edits, checks, default full-local gate, model/effort/calibration status, escalation triggers and remaining allowances. Any conditional CI-authoritative trial needs section 6's separate approval and proved eligibility; high risk is excluded.

Create one contract or one slice plan with all contracts/dependencies/outcomes/budgets. Default five distinct decision/outcome scenarios; approve a larger coherent contract once. Equivalent values under the same decision are coverage examples. New rejection/interpretation/guarantee/boundary meaning is another scenario; do not hide it under a parameterized test. Inventory operation, invalid input, representation limits, operation-time failure, compatibility and documentation. Plan each baseline against full verification/global coverage; expose infeasible dependencies early. Unchanged-scenario redistribution preserves total budget/used repairs.

A complete explicit mechanical/bounded request may authorize execution. Record the actual instruction/revision and concise read-back without a duplicate yes. High-risk contracts and policy changes require explicit approval of the identified proposal; large plans may be approved together. Routine named role/check/repair transitions are authorized within scope/allowance. Missing material answers, changed behavior/interfaces/permissions/sharing, downgrade or allowance/budget extension needs an answer. Silence is no approval; architecture approves no scientific feature.

Prepare [PUBLIC-PACKET](../../../docs/agentic-software-delivery-v1.0/templates/PUBLIC-PACKET.md) for A/B and [CANDIDATE-PACKET](../../../docs/agentic-software-delivery-v1.0/templates/CANDIDATE-PACKET.md) for workers/final reviewers. Blind inputs exclude implementation/history/conversations, implementation-bearing state, coverage maps and existing lessons. Sanitize correction findings into approved public reproductions; dependency mapping comes only from tests/requirements. Shared fixtures/oracles expand review; new meaning returns here. Coordinator launches actual fresh native high-risk roles and fresh independent bounded/policy review sessions without author history. A role already launched performs its packet directly. Retain one Current state, spending/windows/repairs and explicit unknowns; fresh context renews nothing.
