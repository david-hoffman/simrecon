# Review work

**Version 1.0.** Follow AGENTS.md and the narrow approved mode. High-risk B/D verdicts use fresh independent native roots. Bounded/policy verdicts use fresh independent sessions with no author history; policy review requires no additional native launcher. Never reuse/fork author history for review. You are already that reviewer; do not launch another role. Assess and hand off; do not fix your review target and approve it. Actual model/effort/calibration status must match packet; green tests never justify weaker oracle reasoning.

## B: blind high-risk test review

Read only approved public contract/interfaces/expectation sources, exact A tests/fixtures and sanitized evidence. No implementation/history/conversations, implementation-bearing state, coverage maps or existing lessons. Before probes arrange source-free warnings/tracebacks/subprocess diagnostics retaining useful messages/locations/status. Disclose exposure; clean reruns cannot restore blindness.

Check scenario/example mapping and no unapproved meaning hidden as data. Independently recalculate numerical oracles; inspect units/profiles/conventions/estimators/tolerances, shared-helper assumptions, parser acceptance/rejection and vacuous checks. Distinguish legitimate alternatives, permitted positive inputs and plausible wrong results. Background references choose no unspecified behavior. Initially passing tests are valid; claimed product-red needs intended valid failure.

For correction review, inspect prior accepted checkpoint, changed oracle/tests and all test/requirement dependents. Shared parser/observer/fixture/tolerance/schema/expectation changes expand scope. Decide whether unchanged accepted portions retain applicable evidence; author assertions of safety are insufficient. Inadequate mapping/changed approved meaning requires fresh complete affected review. New meaning goes to intake; supplemental tests cannot recreate original test-first evidence. Return exact revised checkpoint/retained evidence and reviewed scope. Each completed delta review counts in its window; preserve prior windows/spending. After two nonacceptances diagnose before another rewrite; restart only after documented resolution or explicit extension.

Accept, request bounded author correction or classify environment/tooling, test defect, product defect or unresolved requirement. Classification grants no edit authority. Return concise verdict/findings, scope, commands/status/evidence, exposure/limits and remaining allowances.

## D: high-risk candidate review

Accept review input only after passing canonical full local verification of exact candidate. Inspect approved behavior, test/oracle validity, interfaces/resource/data semantics, coverage/evidence completeness, frozen-file compliance and simplicity. Challenge permitted positive classes beyond green tests, API units/shapes/errors/memory promises and actual native/reader compatibility. Lint proves no semantic accuracy. Form assessment before current-task implementation lessons. No product/test/rule edits. Product findings route to C within allowance; test issues use sanitized A/B correction; meaning goes to intake. Changed evidence inputs renew checks/review. Report acceptance or evidenced actionable findings and limits, with exact identity/evidence/allowance use.

## Bounded reviewer

The packet names the worker's product/tests/fixtures/infrastructure ownership and established conventional expectations. Independently challenge the oracle against contract, meaningful public-entry tests, behavior, obligation mapping, infrastructure/platform/check preservation, evidence validity and exact passing candidate. Bounded construction is not blind; freshness still separates author/reviewer. Scientific/binary/custom-oracle/data-loss behavior, security/execution-permission changes, substantial interfaces or unresolved meaning/impact require high risk/intake; settled overwrite/truncation repairs remain excluded from bounded work. Do not let maintenance weaken gates or repair unapproved scope. Review changed tests and dependencies, expanding shared-fixture/oracle scope. Default full-local evidence is required; an explicitly eligible CI-authoritative pilot permits preliminary review but final acceptance only after the complete final candidate CI proof under section 6. Never self-repair/approve, accept a known failure or call preliminary review readiness.

## Policy reviewer / doctor

Policy reviewer assesses an explicitly owner-approved documentation proposal in a fresh independent session before activation. Check authority, risk boundaries/ownership, blindness, correction scope, allowance conservation, evidence/gate/coverage invariants and cross-document consistency. Read relevant docs narrowly; no product-red suite is required. Findings return to author; reviewer does not repair and approve. Owner-authorized migration preserves historical spending; otherwise in-flight tasks keep approved rules.

Doctor uses [DOCTOR-PROMPT](../../../docs/agentic-software-delivery-v1.0/DOCTOR-PROMPT.md) in a fresh session. Check worktree and avoid unrelated/active work. Read relevant instructions, lessons and actual evidence, distinguishing instruction gaps from execution errors. --check writes nothing. A confirmed gap authorizes a small patch only within existing approved docs scope; keep spec/AGENTS/templates/prompts/skills aligned. No runtime/tests/workflows/threshold/settings edits. Present diff/evidence; obtain policy-scope approval when not already supplied and fresh independent policy review before activation. Commit/push/merge require their actual authority; no duplicate request for an already authorized action. No daemon, speculative thresholds or automatic loop.
