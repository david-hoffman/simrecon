## 6. Match agent capability to judgment, then measure

**Adopted selection criteria with [recorded calibration](../operations/calibration-results.md), not a fixed model ranking.** Model capability and reasoning effort are separate choices. Use a capable default for unfamiliar scientific/binary work; reduce either only after relevant calibration shows acceptable results. Luna/Sol names, if used in configuration, are examples rather than evidence of price or task quality. No current pricing or comparative capability claim is established here.

| Role | Hardest judgment | Starting reasoning proposal |
|---|---|---|
| A | Derive independent oracles/fixtures; settle approved units, axes, bit patterns, tolerances and distinguishing positive/error inputs | High for scientific/binary/custom-oracle work; a lower setting only for calibrated deterministic cases. A may need more capability than C. |
| B | Independently recalculate expectations; find copied outputs, shared assumptions, vacuous assertions and plausible wrong accepted results | At least the task's demonstrated oracle-review capability; substantial reasoning for scientific/binary work. B is not a cheap syntax pass. |
| C | Implement the frozen contract simply; preserve resource/data semantics, bounded memory and unrelated interfaces | Scale to algorithm, architecture and lifecycle complexity. Straightforward implementation of a difficult oracle may need less reasoning than A/B. |
| D | Challenge behavior beyond passing tests/coverage, permitted-input classes, real native/reader compatibility, scope and simplicity | Substantial reasoning for uncertain/high-risk behavior; a lower setting only after relevant review calibration. |

The bounded-route worker must handle both oracle design and implementation; its fresh reviewer must assess both, so two sessions do not imply weaker models. Mechanical work can use a lighter agent plus deterministic checks when impact is settled. A dependency/check task may still demand expert judgment despite a small diff. Same-model authors/reviewers are permitted, but fresh independent derivations and contract probes matter; using different model names alone does not establish independence.

Before a pilot, record model/effort per role, task class, quality criteria and escalation triggers. Reuse applicable calibration for unchanged configurations and task families; probe changed settings or unrepresented complexity rather than benchmark each role anew. Use small public/synthetic cases with known defects and independently justified answers; do not feed implementation lessons to blind A/B. Compare missed/false findings, oracle validity, first accepted checkpoint, rework and total role/check cost, not only initial tokens. Calibration has its own approved budget and adds no permanent role or mandatory mutation platform.

Classify a failure first. Unresolved semantics go to intake; environment failures go to setup; test/product findings follow role routing. A stronger setting or model is a bounded experiment only when the evidence indicates a reasoning limitation and authorization/budget remain. It is not an automatic remedy after two B nonacceptances: diagnosis and existing restart/extension rules still apply. Preserve every attempt, review round, C repair and spending; replace an exposed blind author with a fresh permitted session. More effort cannot approve missing behavior.
