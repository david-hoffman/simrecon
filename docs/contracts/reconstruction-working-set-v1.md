# Reconstruction working-set investigation contract

**Version 1.0.** Report-only contract for [issue #116](https://github.com/david-hoffman/simrecon/issues/116).
Git versions revisions. The [task](../tasks/reconstruction-working-set.md) owns the sole Current state.

## 1. Authority, outcome and baseline

The human authorized actual intake, a reproducible investigation with experiments,
ranked individual handoffs, fresh independent scientific measurement review,
the exact full Ubuntu `make verify` gate and a stacked PR. This contract records
that authority; it creates no additional document-approval checkpoint. The
coordinator owns integration, process scheduling, commits, push and PR. No merge,
release or manual issue closure is authorized.

The outcome is evidence for selecting the next memory change, not a numerical
implementation, new acceptance tolerance, process ceiling, latency ratio or
full-volume success requirement. A 16 GiB workstation is a feasibility objective
with caller/OS headroom to measure. This host cannot certify that workstation.

Public-main intake baseline is `b344e41a8b52de76d7cbbf8450319893904c3b8f`.
Preserve the complete original RM84 public-main baseline and its artifacts;
historical evidence is not silently regenerated or rewritten. The RM84 task
points to ignored `artifacts/rm84/`; preserve whatever corpus is actually present
and explicitly inventory missing historical repeats/receipts. The public tracked
code/frozen tests are not proof that absent numeric records exist. Final experiments
and verification must bind the accepted #115 result after accepted #112, with
the coordinator recording exact base/head/tree/dirty and dependency identities
outside self-identifying tracked bytes. Intake's provisional base is not the
final scientific candidate. Recheck materially changed source, dtype policy,
representation checks and dependencies before execution; do not compare transient
branches as accepted baselines.

## 2. Boundaries and ownership

This is a scientific report-only investigation: one nonblind investigator and a
fresh independent scientific measurement reviewer. It changes no product behavior
or test oracle. A/B/C/D implementation roles and fabricated product-red tests are
inapplicable here. A proposed numerical/storage implementation returns through
its own intake and required roles before any product edit.

- Intake author: this contract, the task and the two named packets only.
- Investigator: analysis-only harnesses, deterministic fixture extensions, raw
  observations, calculations and report under
  `docs/reports/reconstruction-working-set/`. Existing source, tests, fixtures,
  RM84 evidence, lock, Make/workflows, policy and installed gates are read-only.
- Reviewer: report-only independent assessment under that directory, at a
  separate coordinator-named review destination; no repair of the review target.
- Coordinator: launch/accounting records, resource release, integration,
  exact-candidate verification evidence, PR presentation and housekeeping.

No disk-backed execution, precision implementation, size-domain expansion,
retired C execution, export benchmark, dependency/gate migration or product API
is commissioned. Analysis scripts are not shipped or installed runtime, routine
tests, automatic growth loops or replacement verification tools.

## 5. Observer, liveness and attribution

Primary measurements use unprofiled fresh processes. Set
`OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS`, `MKL_NUM_THREADS` and
`NUMEXPR_NUM_THREADS` to `1` before startup; record effective backend/FFT workers
and unsupported controls. No child numerical workers or image export are part
of a workload. The external observer is identified separately from the measured
process; its own memory/CPU/disk use is not attributed to reconstruction RSS.

Record native `resource.getrusage(RUSAGE_SELF).ru_maxrss`, Linux KiB × 1024
conversion, pre-call high-water, call-only monotonic seconds and final raw peak
bytes including imports, generation, hashing, caller inputs, numerical/backend
workspaces, result and observer work inside the process. Peak minus pre-call
high-water is not an isolated workflow peak. Preserve raw integer observations,
not rounded chart values alone. Include retained reachable NumPy backing bytes
counted once and separately labelled incomplete Python-metadata estimates.

Use existing `workflow_stage` boundaries (declaration, optional layout,
preparation, estimation, per-time reconstruction, result) as the initial stage
map. An analysis-only wrapper or `sys.setprofile`/`sys.settrace` observer may
record stage entry/exit and selected allocation/release points without product
edits. Add process RSS sampling with declared interval (initial design 10 ms),
sample count and timestamp alignment. Stage `ru_maxrss` is cumulative high-water;
an unchanged value does not mean no stage allocation. A sampled stage maximum is
not an exact instantaneous peak or isolated allocation. Sampling and Python hooks
can perturb timing, allocation and lifetime; retaining frames, locals or arrays
would itself change the subject and is forbidden. Log scalar metadata only.

Before relying on attribution, perform matched unprofiled/profiled three-repeat
comparisons at the central case and largest safely demonstrated searched case.
Report RSS/runtime ranges and medians for both, hook/sampler overhead and any
unresolved perturbation. Profile observations support association; they cannot
alone identify native FFT workspace or individual NumPy temporaries. If hooks
change scientific output/branch identity or keep arrays live, reject that observer
and preserve the failed attempt. Hash result/parameter fields to detect accidental
observer changes; hashes supplement inherited scientific evidence, not prove
physical recovery or a new numerical tolerance.

For each allocation family, record source path/function/revision, shape, dtype,
backing/alias ownership, creation, last numerical use, release/publication and
co-live dependencies. A calculated array payload is `product(shape)*itemsize`;
use actual half-storage `X//2+1`, quadrature Q=`2*O-1` and enlarged output geometry.
Count backing allocations once and sum only intervals that overlap. State which
temporary expression lifetimes are source-derived rather than observed. Include
native harmonic scratch even if its allocation is hidden behind a helper.

Source inspection at the provisional baseline suggests hypotheses to check:
workflow preparation uses `acquisition/modes.py::_prepare_acquisition_bands`,
with per-plane on/off frames and full q/off_q storage, not the direct CE02
`preparation.py` full-volume frame path. Keep CE02 contextual and separate.
Compact preparation still owns prepared bands; off preparation has an additional
quadrature family; search builds paired full native overlap volumes; filtering
holds stable prepared source plus destination; assembly overlaps padded and
inverse arrays during FFT and then uses phase/exponential/product temporaries;
multi-time output aggregation may overlap per-time outputs and concatenation.
These are not measured rankings. Full-debug snapshots and traces have different
lifetimes from summary. Do not apply a full-debug sum to summary or add sequential
directions/orders as if all scratch were simultaneous.

Unknown backend workspace, allocator retention/fragmentation, shared pages,
copy-on-write, Python/native metadata, sampling gaps and OS effects remain
unattributed unless directly observed. `tracemalloc` alone cannot measure NumPy/
FFT whole-process memory. Swap/page faults/block I/O are context, not isolated
array ownership. Record actual log/artifact disk use and distinguish logical file
size from allocated blocks; no disk-array execution follows.

## 6. Preflight, scheduling and stopping

The coordinator supplies the pinned Ubuntu interpreter and worktree `.venv` and
owns resource scheduling. Intake runs no install, test, numerical experiment,
benchmark or full verification. Before the investigator's numerical work, record
64-bit platform/interpreter, locked dependency/import health, source/fixture/
harness/lock identities and current host/cgroup limits. Do not install or repair
an environment outside the coordinator's setup authority.

Before each workload or growth step:

1. Check declared dimensions, retained element/index/count and native-intp extents,
   output products and actual transfer stencils against the accepted
   [wide allocation domain](wide-allocation-domain-v1.md), using integer
   calculations without allocating the proposed volume. Its superseded
   signed32/unsigned32 allocation-byte-only caps do not apply.
2. Record actual-time host/exposed-machine memory and every visible effective
   cgroup ancestor, namespace/membership/limit correspondence for the workload,
   swap, rlimits, competing tasks, disk context and intended observer/workload
   process IDs. Missing observable bounds or correspondence blocks admission.
   Ancestors outside the exposed machine that cannot be observed remain explicitly
   unknown, never absent or unlimited; root-looking paths alone prove no mapping.
3. Produce a conservative co-live payload estimate, measured smaller-case RSS
   envelope and explicit allowance for unresolved native/allocator work plus
   caller/OS/observer headroom. Record the chosen available budget, reserve and
   evidence. Conditional admission requires fresh correspondence evidence, a finite
   observable bound, quantified native/allocator allowance and caller/OS/observer
   reserve, monitored stop margins and coordinator rationale accepting residual
   external-ancestor uncertainty. This is an experiment-specific safety decision,
   not a product cap or human-set numeric limit. If no defensible allowance fits
   current headroom, mark the case unmeasured and do not launch it. No monitor
   guarantees zero OOM risk.
4. Obtain coordinator scheduling release for that exact case. Run at most one
   numerical experiment at a time in the shared resource domain; do not overlap
   full verification, installs or other campaign numerical work.
5. Use an external bounded monitor with recorded deadline and current-memory
   stop threshold derived from that preflight. Stop/terminate the owned process
   on threshold, timeout, deteriorating headroom, representation refusal or
   scientific failure; record signal/status/last sample and any monitor race.
   A deadline is a recorded per-attempt safety measure, not a human total budget.
   Do not restart automatically or grow after failure without diagnosis.

Never deliberately OOM, rely on swap rescue, or claim a monitor guarantees zero
overshoot. Preserve all refused, stopped and failed trials. A refusal before
allocation is a useful boundary observation, not measured execution at that size.
Report largest demonstrated case per mode/search, next proposed unmeasured case
and exact stop reason. No crop extrapolation is full-volume evidence.

Accepted #115 removes the old allocation-byte-only refusal for the original
`(T,D,P,Z,Y,X)=(1,3,5,32,2048,2048)`, L2/A1 geometry on the supported 64-bit
platform. Retained signed/native/stencil and scientific constraints still apply.
Its output `(1,32,4096,4096)` has 536,870,912 voxels; the historical
`8*Xo*Yo*Zo=4,294,967,296` byte expression is no longer an unsigned32 ceiling.
Representation validity supplies no safe-allocation inference or execution
requirement. [Source-derived liveness](../reports/reconstruction-working-set/analysis/integrated-parent-reconciliation.md)
calculates 32,227,983,360 bytes co-live for a hypothetical float32 caller, its
owned snapshot and complex128 prepared bands alone. This logical payload lower
bound exceeds the previously observed exposed 16 GiB bound; it is not measured
RSS or actual-time admission evidence. The target remains unmeasured and not
allocation-admitted. Do not relax checks or promise completion on 16 GiB.

## 7. Report, ranking and acceptance

Publish one report with reproduction commands, fixed workload manifest, raw
attempt ledger, all successful/failed/stopped records, aggregate ranges/medians,
stage/lifetime table and largest/next-size envelope. Include commit/tree/dirty,
base/integration, input/observer/lock hashes, Python/NumPy/SciPy/FFT/backend/
allocator/thread identities, host identifier without private paths, OS/kernel,
process limits, memory/swap/page-fault/disk context and units. Missing metering is
unknown. Three repeats do not justify a general statistical or workstation claim.

Rank bounded changes using measured workload relevance, calculated co-live bytes,
observed attribution strength, likely benefit, scientific/ownership risks and
implementation dependencies. Every ranked recommendation gets an individual
handoff with evidence IDs, proposed file/mechanism scope, excluded semantics,
invariants, paired valid/error/mode risks, proposed public verification and matched
resource experiment. Unsupported benefit estimates remain predictions; unresolved
backend peaks can limit ranking confidence. A handoff commissions no repair.

Fresh review must independently check generator meaning, representative branches,
process matching/provenance, units, payload arithmetic/aliasing/live intervals,
sampling/observer limits, safe stops, preservation of failures/RM84 evidence,
dtype claims and rankings. The reviewer may perform cheap read-only arithmetic
and reproduce explicitly scheduled experiments; resource authority stays with
the coordinator. Findings return to their named author, followed by fresh required
review of affected evidence. Reviewer never repairs and accepts its own change.

The observer/report is reusable only with revision-specific refresh. Material
inputs include product commit/tree/dirty and accepted dependency stack, generator/
formulas/constants/shapes/modes/search/reuse, input hashes/dtypes, harness/observer
code and configuration, lock/interpreter/NumPy/SciPy/FFT/backend/allocator/thread
settings, host/cgroup/rlimits/headroom, timing/hash/retention traversal scope and
process orchestration. Later #117/#118 memory changes invalidate affected #116
liveness/attribution/peak claims before dependent #119/#120 design relies on them.
The coordinator commissions a narrow refresh on that later accepted base: retain
original trials, recalculate changed families, rerun affected matched contrasts

only explicitly unchanged applicable evidence. Do not restack this earlier report
