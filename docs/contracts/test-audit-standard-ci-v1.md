# CI-STANDARD-01: standard complementary jobs and existing validators

**Version 1.2.** This supersedes the unimplemented CI-SHARDS-01 mechanism. It continues the
owner's test-audit task: Ubuntu-only continuous integration (CI), complete valuable
proof and a measured required-job interval strictly below 300 seconds. Disk
lifecycle already has accepted exact local evidence. No scientific behavior,
numerical oracle, test assertion, full-local gate or selected coverage target is
relaxed. No Superpowers, paid runners or token expansion.

## Diagnosis and route

The inherited parallel-execution contract trusts a genuinely qualified maintained
scheduler. It requires exactly-once qualification, not a new recurring adversarial
transcript protocol. CI-SHARDS-01 added generic interfaces and guarantees beyond
the owner request. Before any implementation or accepted B checkpoint, fresh
clean-context Astra recommended removing that unshipped mechanism and preserving
the original obligations with standard tools and unchanged existing validators.
This is a scope simplification, not a lower risk classification of that custom
oracle. A recurring custom completeness predicate would still be high risk,
including if hidden inside YAML.

The replacement is **bounded conventional dependency/platform/check maintenance**:
ordinary import guard, passive pytest metadata, standard job wiring and unchanged
validator calls. One named worker and fresh independent exact-candidate reviewer
apply. Review includes the scheduling amendment, preserved automatic gates,
oracles, shared fixture impact, actual partition proof and evidence limits.

The two proposed generic A files were never accepted or published. Let A close
its handoff, retain their exact sources/reports/commands/evidence and every prior
charge, then retire only positively identified obsolete untracked source files.
No old rejected checkpoint becomes acceptance of this replacement.
