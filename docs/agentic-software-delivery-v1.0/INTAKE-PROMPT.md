# Intake prompt

**Version 1.0** Use intake. This prompt defines a conversation boundary, not an authorization service.

```text
Record and clarify this task or architecture request. Reuse settled project context;
resolve only missing/materially inconsistent architecture, then resume the original
request. No unrelated redesign or repeated settled questions.

A direct human request authorizes its intended scope for every route, including high
risk and policy amendments. Record the actual instruction and a concrete contract;
do not require approval of documents that restate the request. Ask only for missing
material decisions, unclear/outside-request objectives or human-required external
authority. Use concrete alternatives/defaults with consequences. Silence supplies
no missing answer. Expected results follow the contract, applicable primary reference
or mathematical invariant. Resolve units/conventions/estimators before tests; coverage
chooses no meaning. For a bug separate reproduction, expectation and hypotheses.
Investigate uncertain causes before diagnosed scoped repair.

Select route by impact/uncertainty: mechanical one worker; bounded worker with explicit
named product/test/fixture/infrastructure ownership plus fresh independent reviewer;
high risk fresh blind A/B, restricted C and fresh D. Mixed highest tier unless independent
contracts justify splitting. Policy amendment/adoption uses human-requested docs scope
and fresh independent policy review before activation, never mechanical self-classification.
Dependency/check maintenance always gets independent review; new execution/security
boundaries and data-loss behavior are high risk, including settled overwrite/truncation
repairs. Preserve all gates and high-risk C frozen-file restrictions. Never lower risk
to evade review.

Record route/reason/transitions, named edits, checks, model/effort/calibration status,
default full-local gate and diagnosed escalation triggers. Routine role transitions,
needed in-scope checks, diagnosed corrections and fresh required reviews follow the
human request without repeated permission. There is no default numeric cap on scenarios,
B reviews, C/bounded repairs or execution budgets, no review-window opening approval,
and no exhausted-default-allowance stop. Explicit human-set limits/units/hard stops
still bind. Record absent limits as not set, missing measurements as unknown.

Create one task or a plan with all coherent slice contracts/dependencies/outcomes and
actual limits. Map every distinct decision/outcome, rejection, interpretation,
guarantee or boundary as a scenario; equivalent values are coverage examples.
Test/branch counts do not define scope. Inventory operation, invalid input,
representation limits, operation-time failure, compatibility/docs and paired
permitted-positive cases. Every baseline must support full verification/global
coverage; expose infeasible dependencies before dependent work. Independent tasks
use worktrees; dependent slices wait for completed prerequisites.

No executable tests or product code in intake. Missing or outside-request meaning
returns here for the material decision, not another document-approval interview.
Splits/redistribution preserve objective, dependencies, cumulative attempts and actual
limits. Diagnose recurring failures and each correction with evidence; continue within
named ownership until the objective is complete or an actual blocker remains.
No daemon or uncontrolled automatic retry loop. Context reset restores no blindness;
migration erases no attempts or spending and rewrites no historical records.

Prepare narrow public A/B packets: authorized contract/scenarios/examples/interfaces/
sources, exact test revision, source-free diagnostics, checks, output/completion,
model/effort, cumulative attempts/spending and actual limits. Exclude implementation/
history/conversation/status/coverage maps/lessons; sanitize corrections into public
reproductions and test-requirement dependencies. Shared oracle/fixture changes expand
fresh independent review; new meaning returns here. Use candidate packets for other
roles. Coordinator owns actual fresh launches.

Conditional CI-authoritative evaluation must be part of the human request and meet
section 6 effective native controls/trusted complete CI/base/artifact-version proof.
High risk, unknown evidence and own-gate edits keep full local gating. A green PR
activates nothing. Merge/release/external messages require explicit human authority
for that action. Start with known facts and the highest-impact unresolved decision.
```

Append request, sources and actual human-set constraints. The contract records authorization; it creates no additional permission checkpoint.
