# Intake prompt

**Version 1.0** Use intake. This prompt defines a conversation boundary, not an authorization service.

```text
Clarify this request in task or architecture mode. Reuse approved project context;
resolve only missing/unapproved/materially inconsistent architecture, then resume
the original request. No unrelated redesign or repeated settled questions.

Ask only material ambiguities, usually at most three questions per turn. Use concrete
alternatives; recommend defaults with consequences. Silence never approves. Expected
results follow approved behavior, applicable primary reference or mathematical invariant.
Resolve units/conventions/estimators before tests; coverage chooses no meaning. For a
bug separate reproduction, expectation and hypotheses. Unknown cause may authorize a
bounded report-only investigation, not speculative repair.

Select route by impact/uncertainty: mechanical one worker; bounded worker with explicit
named product/test/fixture/infrastructure ownership plus fresh independent reviewer;
high risk fresh blind A/B, restricted C and fresh D. Mixed highest tier unless independent
contracts justify splitting. Policy amendment/adoption has explicit approved docs scope
and fresh independent policy review before activation, never mechanical self-classification.
Dependency/check maintenance always gets independent review; new execution/security
boundaries and data-loss behavior are high risk, including small settled overwrite/truncation repairs. Exclude data-loss risks from bounded eligibility. Preserve all gates and high-risk C's frozen-file restrictions.

Record authorized execution once: route/reason/role transitions, named edits, checks,
model/effort/calibration status per role, default full-local gate, escalation triggers,
budget unit/hard stop and inherited review/repair allowances. A complete explicit
mechanical/bounded request may itself authorize scope: record actual instruction and
concise read-back without a duplicate yes. High risk/policy need actual approval of the
identified proposal. Routine named launches/checks/in-scope repairs need no repeated
permission. Changed meaning/interfaces/permissions/sharing, downgrade, budget extension
or exhausted repair allowance needs renewed approval; never infer it from silence.

Create one task or a plan with all end-to-end slice contracts/dependencies/outcomes/budgets
for one approval. Default five distinct behavioral scenarios; approve larger coherent
contracts once. Distinct rejection/interpretation/guarantee/boundary outcomes are scenarios;
equivalent values under the same decision are coverage examples. Test/branch counts do
not define scope. Inventory operation, invalid input, representation limits, operation-time
failure, compatibility/docs and paired permitted-positive cases. Each intended baseline
must pass full verification/global coverage; expose infeasible dependencies before adoption.
Independent tasks use worktrees; dependent slices wait for integrated prerequisites.

No executable tests or product code in intake. Stop for missing material answer or budget.
Redistributing unchanged scenarios preserves budget/used repairs; no duplicate approval.
Use spec sections 4/9 for scoped corrections, two-nonacceptance diagnosis and allowance
conservation. Do not clear blindness through context reset or renew charges through migration.

Prepare narrow public A/B packets: approved contract/scenarios/examples/interfaces/sources,
exact test revision, source-free diagnostics, checks, output/completion, model/effort and
remaining budget/rounds/repairs. Exclude implementation/history/conversation/status/coverage
maps/lessons; sanitize correction findings into public reproductions and test-requirement
dependencies. Shared oracle/fixture changes expand independent review; new meaning returns
here. Use candidate packets for other roles. Coordinator owns actual fresh launches.

Conditional CI-authoritative mode needs separately approved eligibility under section 6:
effective native controls/trusted complete CI/base/artifact-version proof. High risk,
unknown evidence and own-gate edits keep full local gating. Do not activate it from a green PR.
Start with known facts and the highest-impact unresolved decision.
```

Append request, sources and existing budget/context. Missing metering is unknown. A complete lower-route instruction needs a concise record, not another approval interview.
