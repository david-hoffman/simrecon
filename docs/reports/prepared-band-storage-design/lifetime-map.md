## Identity and successful ownership proof obligations

The one canonical byte stream is `q[0,0]`, `q[0,1]`, …, `q[T-1,D-1]`, each in Q,Z,Y,half-X C order, normalized component-wise little endian without evaluating/rounding values. Aggregate shape/dtype/name remain separate identity metadata. The streaming equivalence follows concatenation of these adjacent byte intervals into one digest; whole-block digests cannot be composed into the existing SHA256. Finite signed-zero complex patterns and strided/endian public cases require independent byte oracles later. Existing off/input/diagnostic identities keep exact names and projection ordering.

An implementer must show for every successful release: (a) preparation has returned, (b) digest and finite-buffer readers have returned, (c) estimator/closures/source locals have returned and no q view was published, (d) one-time/validated descriptors store only the mutable table and logical metadata, (e) all initialization borrows/iterators have ended before filtering, (f) direction helper/current borrow/view has ended, (g) the owning slot is cleared and no duplicate collection/cache/base holds the root. Remaining table references then cannot retain a removed slot. A `del original` alone proves none of this on actual118. Retained exception frames remain an explicit failure limit. No live-object, backend or RSS observation was performed by this author.
