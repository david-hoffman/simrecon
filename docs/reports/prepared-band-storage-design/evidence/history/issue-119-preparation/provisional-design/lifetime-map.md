## Aggregate validation and failure sequence

The exact validator sequence must be reconciled rather than replaced by a convenient per-block check. Existing downstream `modes.py:154–220` first validates shape/count/mode and q type/dtype/shape, noise type/dtype/shape, sampling/zoom/scale/source metadata, signed/global products, output and aggregate native extents; only then q finite, noise finite and noise positivity. Preserve that order and categories for the private logical collection. Preparation's separate finishing path validates/transfers q first, noise second, then diagnostics in field order (`1051–1087`). Original full/direct paths stay intact.

Before scan/hash/copy/backend work, preserve signed dimensions and products including T*D*Z*P and off/header exposure counts, output extents and aggregate native addressing for the entire logical collection. Native shape/stride bytes use actual widths; empty diagnostic extents retain existing rules and do not create valid empty scientific inputs. Per-block representability alone is insufficient. No aggregate signed bound beyond existing source semantics, obsolete byte-only limit or arbitrary RAM cap is added.

Do not perform off/noise/diagnostic checks early just to release a block before later preparation work. A later numerical failure must retain its prescribed priority against deferred final checks. During filtering retain the final all-filtered finite check after every direction, not new per-direction finite result checks. Preserve later result finite checks as well. New block scans must not fabricate t/d error context during formerly aggregate validation: actual exception stage/category/available indices and cause chains remain the comparison obligation.

On any late failure return no partial image/trace and mutate no caller inputs. Workflow MemoryError and interruption behavior remain. Tracebacks and causes can retain failed frames/locals; successful-path slot clearing is not an exception-path immediate-free guarantee. Public/direct snapshots remain independent even for valid writable modified bands, noncontiguous or read-only arrays; private owning blocks are not an excuse to impose a new public contiguity restriction.

## Canonical identity lifetime

Finish preparation writes/checks, then stream q before estimator execution or any release. Keep one digest and aggregate metadata: name `prepared_quadratures`, logical shape `(T,D,Q,Z,Y,X//2+1)`, normalized little-endian dtype, SHA256 of C-order element bytes alone. Traverse t,d,q,z,y,half-x in increasing order. Chunk boundaries contribute no bytes; a chunk may end within a row or complex array provided components/bytes remain in canonical order.

For independently C-order pair owners, feed bounded contiguous byte spans in logical t,d order. For strided or non-little-endian representations, copy only bounded logical C-order chunks and normalize each multi-byte component without numerical rounding. Preserve signed zeros, complex real/imaginary order and exact supported element bits. Never stack/concatenate all blocks or produce a whole normalized duplicate. Complete aggregate/metadata checks precede streaming; chunk buffers/views cannot escape its scope or retain released blocks. Existing input and projection identity names, shape/dtype metadata and sort/field ordering remain exact. No compact off-q identity is invented; its finite validation is still mandatory.
