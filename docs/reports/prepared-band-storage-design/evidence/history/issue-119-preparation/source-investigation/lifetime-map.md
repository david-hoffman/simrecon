## Producers, views and retaining owners

Here `q` means the prepared on quadratures, shape `(T,D,Q,Z,Y,X//2+1)`, complex128, `Q=2*O-1`. Let `H=Z*Y*(X//2+1)`: its analytical payload is `Bq=16*T*D*Q*H` bytes. This is an array payload, not resident memory. A time or direction view contributes no independent backing that can be released separately.

All-q/raw co-residency exists before later release opportunities: raw snapshots survive until preparation completes; q and optional off q are allocated before the loops. Splitting the same q payload into independent blocks cannot by itself reduce that total during preparation. Historical #116 source context identifies the original target's caller + same-dtype snapshot + prepared-q payload alone as exceeding its prior exposed 16 GiB setting; this is not a current admission/RSS result (`README.md:138`). CE02 direct preparation's full float64 frames are a different route (`preparation.py:406–453`), not CE06 workflow plane scratch.

## Earliest potential release boundaries under the existing stage order

These are conditional analytical opportunities for future interfaces, not properties of accepted #116.

- **Independent time owners:** after all-T preparation, canonical q identity and all-T estimation, time t must still survive its native filter. At the first ordinary workflow call boundary, after that time's known reconstruction returns, an owning container could remove t and the temporary record/validated aliases could be gone. The existing workflow never does this. A narrower inside-call release is conceivable after filtering t finishes and all q aliases are cleared, before assembly, but simply retaining `bands`/`used`/`quadratures` defeats it. Time-only splitting leaves T=1 unchanged.
- **Independent (t,d) direction owners:** after global preparation/identity/estimation, source coefficients for d have no other-direction consumer in the native filter. Once copying initial destination values and all reflected partner reads/writes for d finish, that prepared d backing has no future successful-path numerical reader. Releasing it then requires changing broad-array/record aliases; the current helper accepts a whole time array and keeps them. This could affect T=1,D>1, where time-only storage does not. It still retains every direction's filtered values until assembly begins and preserves filtering-before-assembly. It does not license interleaving filtering and assembly.
- **All directions' parameters remain mandatory:** filter scale loops through all directions and signed orders, summing transfer/amplitude/inverse-noise powers (`known_parameters.py:573–598`); precise taper also uses the carrier set. These are parameter/transfer dependencies, not reads of another direction's q. Passing only the local direction as if global D were one would change normalization, denominator, support/taper or order. Keep global geometry and full parameter tables while making coefficient ownership local.
- **Off owners:** last preparation coefficient use for off(t,d) follows its last z combination, but successful-path release is not justified there while the final off finite check is still pending. Full output additionally requires retaining off q and independent event snapshots. No early off release is established by this report.

Owner containers, temporary slices, broad `_UsedBands` references, local `quadratures` variables, estimator.data and exception tracebacks must all be considered. On failure, translated exceptions retain causes and can retain frames/locals (`result.py:85–144`); no partial result escapes, but immediate deallocation is not promised. Logical last read, Python unreachability and allocator/RSS release are three different statements. No freeing or resident-memory reduction was observed here.

## Global validation and canonical identity barriers

`modes.py:154–220` checks complete logical T/D/P/Z/Y/X, odd Q<=P and O>=2 downstream, exact q/noise shapes/dtypes, global D normalization, sampling/zooms/source identity, signed counts including `T*D*Z*P`, output extents and aggregate native bytes before q/noise finite scans. `layout.py:119–127,262–347` supplies native stride/byte and on/off aggregate checks; workflow additionally validates original/effective geometry and off/header aggregates before scans, copies and hashing (`config.py:256–360`). Fragmenting allocation does not waive logical aggregate validation or justify a new per-block-only admission rule. Signed element/index limits and native bytes are distinct; no old byte-only cap or invented memory cap should return.

Public/direct/full inputs include valid writable mutated bands and read-only/noncontiguous arrays. Public estimation/known reconstruction retain independent snapshots; compact private borrowing is guarded by private type plus compact context. A future private block representation must preserve that boundary and cannot reject valid direct-stage strided values or redefine PreparedBands noise `(D,O)` as AcquisitionBands noise `(T,D,O)`.

At compact preparation finish, q finite is checked first, noise next; diagnostics then undergo extent/finite checks in declared field order, including off q even though it is not projected (`modes.py:1051–1087`). Filtering ends with a finite scan of all filtered output (`known_parameters.py:762`), and result finishing checks arrays again. Do not move a discarded block's check earlier than a later numerical failure or omit it merely because no future coefficient reader exists. Data-dependent failure timing/priorities, stage/index context, MemoryError/interruption and no partial-result behavior remain obligations.

The canonical q identity must have name `prepared_quadratures`, complete logical shape `(T,D,Q,Z,Y,X//2+1)`, dtype normalized to little endian, and one SHA256 of the logical C-order element bytes. It excludes shape/type bytes; those stay separate metadata (`CE07:406–418`, `identity.py:160–176`). Same-type finite complex128 values, signed zeros and real/imaginary component order must survive unchanged.

A byte-equivalent streaming specification is to update one digest in increasing **t, d, q, z, y, half-x** order after preparation has finished its writes/checks and before estimation. Whole C-contiguous time blocks can be fed in t order; C-contiguous (t,d) blocks in nested t,d order. Direction-major owners containing several times must interleave their time slices; feeding each direction's entire T extent would hash a different sequence. For noncontiguous blocks, bounded logical rows/chunks must be materialized in C order and endian-normalized without value rounding, then fed to the same digest. Chunk boundaries add no bytes. Endian conversion must reverse each multi-byte component correctly, preserving complex real/imaginary ordering. Metadata must describe the aggregate logical array, not the chunks. No concatenation/stack/full duplicate is required by SHA256's ordered byte stream definition. The current `array_identity` may make a whole normalized copy for noncontiguous/non-little-endian input; a block-stream path is a future obligation, not existing code.

Off q has no compact identity field: validate it without inventing one. Full off storage remains required. Noise/other projected arrays keep their exact names, shape, normalized dtype and ordering; all original input identities, including superseded declarations and noncontiguous inputs, remain pre-conversion identities.
