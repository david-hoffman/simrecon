## Findings requiring source correction

### F1 — A missing current-RSS observation disables that stop condition

Source defect; material monitor safety gap. [observer.py:101](/workspace/work/issue-116/docs/reports/reconstruction-working-set/observer.py:101) returns a sample without `VmRSS_bytes` when status is unreadable or lacks that field. [run_attempt.py:262](/workspace/work/issue-116/docs/reports/reconstruction-working-set/run_attempt.py:262) uses `sample.get("VmRSS_bytes", 0)`, treating unknown RSS as zero. If the direct child remains live and its cgroup file and the host/ancestor observations remain readable, neither terminal collection nor those other checks forces a stop. The monitor can continue with its admitted process-RSS guard inactive until another threshold/deadline trips. A failed status read is not inherently proof of child exit; the second exact-PID wait already distinguishes the terminal race.

Correction: after the second terminal check, distinguish missing/unusable process RSS from a measured zero and stop/classify loss of required observation. Preserve the sample and terminal-race behavior. This follows the explicit external current-memory stop obligation, rather than proposing any new numeric threshold.
