# Explicit policy for unknown-phase carrier selection

`select_volume_phase_carrier` answers a narrow question: does exactly one supplied integer-carrier hypothesis satisfy the caller's fit policy? It runs every candidate independently from the same nominal phase commands, retains every diagnostic row, then returns a sole index, no acceptable row or ambiguity. It adds no physical-carrier identification criterion.

A row is eligible exactly when its returned termination is `stationary`, its dimensionless relative residual is **<=** the converted residual limit, and its local projected phase-information rank is **>=** the exact integer rank limit. These comparisons are inclusive, with no added tolerance. There is no residual ranking, rank preference, alias reduction or deduplication. Duplicate and detector-period alias rows count separately. A valid arbitrarily large rank limit can exclude every row; it is not an invalid-input error. Invalid policy raises the declared error before numerical scanning. Any inherited operation-time failure aborts the whole call without a partial selection. The [contract](../contracts/phase-carrier-selection-v1.md) and [usage guide](../usage/phase-carrier-selection.md) define the interface.

Rechecking the policy against returned fields proves policy composition, not diagnostic accuracy.

Stationarity does not establish a minimum. Small residuals, full phase rank and sole acceptance do not establish physical-carrier identity, a correct local basin, global uniqueness, calibration applicability or uncertainty bounds. Aliases, symmetry, sparse support and different observable dimensions can confound selection. These tiny noiseless periodic examples with nearby starting commands establish no measured instrument accuracy, noise robustness, arbitrary-start recovery or dense scalability. Continuous carrier, drift and gain inference remain outside this interface.
