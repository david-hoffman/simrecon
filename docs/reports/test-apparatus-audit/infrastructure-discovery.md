## Highest-confidence substantial opportunity: qualify actual two-worker scheduling

**Observation:** `src/simrecon/_pytest_policy.py:8` sets `PARALLEL_GROUPS = {}`. The hook at lines 12–20 marks every collected file `serial-rest`. `Makefile:tests` already runs exactly `-n 2 --dist=loadgroup --max-worker-restart=0`. Thus the top-level suite is a single xdist loadgroup: two workers start and collect, but loadgroup keeps all test calls on one worker. Two-worker existence is not two-worker useful execution. This is determined from configuration/dispatch semantics; its elapsed cost is unmeasured here.

A fresh independent reviewer must assess the exact group/keeper mapping and material-input qualification.

**Proposed measured shape:** put independently isolated expensive files into explicit whole-file groups, with default serial-rest preserved.
