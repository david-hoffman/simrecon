## Strong cost leads without elaborate caching

### S1: remove exact repeated local Disc arithmetic, preserving the certificate

`tests/c_acquisition_fixture.py:1311–1428`, especially lines 1418–1420, evaluates `propagate(obs)` twice for every uncertain NumPy operation: once in `observer = propagate(obs) + rounding` and again in `backend = maximum(propagate(total_input) - propagate(obs), 0) + rounding`. The nested `propagate` is pure over unchanged local inputs. Retaining its first result in a local variable eliminates one of three propagation evaluations while preserving the original center, observer column, backend column, expression ordering and final `Disc` outward rounding. For matrix multiplication each propagation contains three matrix products; for scalar filtering it repeatedly evaluates divisions, trigonometric derivatives, margin checks and arrays. This is exact repeated work, not a reason to change any tolerance.

`Disc.__array_finalize__` at 1248–1253 eagerly evaluates `np.zeros(self.shape)` twice as `getattr` defaults even when the source already has observer/backend attributes. Every inherited view/access can allocate and discard those two arrays. A lazy fallback preserves the successful existing-attribute path and still initializes missing radii. `Disc.__new__` at 1240–1245 uses `broadcast_to(...).copy().astype(float)` for each radius, causing a second copy after an explicit copy; a single explicit float copy is a further local candidate. Validate shape, dtype, ownership, aliasing, readonly/strided inputs and empty/scalar cases; do not return broadcast views in place of owned radius arrays.

Disposition remains R for all Disc declarations and their callers. These are support implementation optimizations; they remove no assertion or scientific operation.
