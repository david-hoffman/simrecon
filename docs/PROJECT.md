# SIMrecon project

**Version 1.0.** Git versions revisions.

## Approved architecture and boundaries

SIMrecon is a pristine functional Python/NumPy library for structured illumination microscopy (SIM). The owner approved the functional architecture and first MRC conversion contract on October 1, 2026, then two bounded amendments. [Approval and historical execution accounting](tasks/architecture-intake.md#current-state) identify the accepted revisions. Architecture approval does not approve additional scientific scenarios.

The [public conversion contract](contracts/mrc-conversion-v1.md) defines `inspect`, selected-block `read`, pure metadata/layout `harmonize`, streamed `write`, records/errors and the `simrecon` command-line interface. Explicit acquisition configuration controls interpretation. Modern MRC output preserves pixel bits, original metadata and override provenance in embedded HDF5 metadata. Conversion performs no reconstruction or scientific image correction. Initial compatibility is pinned mrcfile 1.5.4; ImageJ integration is deferred.

[Library boundaries](architecture/library-design.md) and [data flow](architecture/data-flow.md) give architecture context. The historical [reconstruction placeholder](tasks/reconstruction-placeholder.md) is superseded by the separately authorized [known-parameter 2D contract](contracts/known-parameter-reconstruction-v1.md). Its stacked implementation candidate adds `reconstruct` / `Reconstruction2D`; [usage](usage/reconstruction.md) and the [actual signed comparison](reports/reconstruction-comparison.md) describe its finite periodic model, full complex transfer and fractional interpolation limitations. New estimators, defaults, adapters, calibration, viewer integration and performance promises need separate contracts. [Scientific context](SCIENTIFIC-CONTEXT.md) and the [migration roadmap](MIGRATION-ROADMAP.md) identify remaining work. Known-phase separation is integrated with the [explicit-phase v2 interface](usage/phase-separation.md). The integrated [calibration foundations](tasks/otf-calibration-foundations.md) define sampled 2D intensity-PSF preparation, independent mathematical fixtures and a Pyotf optical illustration. The [calibration implementation candidate](tasks/otf-calibration-implementation.md) supplies `prepare_otf` / `Otf2D`; [usage and the signed comparison](usage/otf-calibration.md) describe its explicit origin, sampling and full complex transfer. The owner authorized reconstruction stacked above verified, independently reviewed, unmerged calibration PR #7. This is a local stacked prerequisite, not owner integration or reconstruction acceptance; exact verification, review and integration status belong to the [reconstruction task pointer](tasks/known-parameter-reconstruction.md). Citation-only paper conversions are available; full-paper extraction remains incomplete.

The owner next requested [known-carrier illumination estimation](contracts/illumination-estimation-v1.md) stacked above PR #9. This first parameter-estimation slice fits a common phase offset and modulation from supplied relative steps and full complex OTF overlap. The candidate adds `estimate_illumination` / `IlluminationEstimate`, with an [executed usage example](usage/illumination-estimation.md) and [measured independent comparison](reports/illumination-estimation-comparison.md). It supplies explicit reconstruction inputs; carrier, brightness, independent step errors and drift remain separate scope. Its [execution pointer](tasks/illumination-estimation.md) retains exact candidate/checkpoint/review/check evidence outside tracked bytes. The requested Astra/ultra advisory preference is recorded in [model guidance](operations/model-selection.md) and ASD section 9; advisors do not replace required independent roles.

The owner next requested the roadmap slice stacked above verified PR #11. The [finite integer-carrier scan contract](contracts/carrier-scan-v1.md) now supplies `scan_carriers` / `CarrierCandidate`, with [executed usage](usage/carrier-scan.md) and an [actual measured comparison](reports/carrier-scan-comparison.md). It exposes caller-ordered candidate phase/modulation fits and local information failures without selecting or ranking carriers. Its [task pointer](tasks/carrier-scan.md) owns exact review/check/publication evidence. Robust carrier selection, phase-step errors, drift and later dimensions remain separate contracts.

The owner next requested [threshold-based finite-candidate selection](contracts/carrier-selection-v1.md) stacked above verified PR #12. The candidate supplies `select_carrier` / `CarrierSelection`, applying explicit caller residual, geometric-overlap and modulation bounds and selecting only a sole passing row. It retains complete diagnostics and explicit no-match/ambiguous outcomes, including duplicate-row ambiguity. [Usage](usage/carrier-selection.md) and [independent comparison](reports/carrier-selection-comparison.md) demonstrate its limited policy meaning. The owner next requested the roadmap slice stacked above verified PR #13. The [known-reference periodic translation contract](contracts/translation-estimation-v1.md) now has an implementation candidate supplying `estimate_translation` / `TranslationEstimate`: all-pixel normalized RMS on every canonical integer-pixel shift and explicit caller ambiguity tolerance. [Executed usage](usage/translation-estimation.md) and an [eight-case measured comparison](reports/translation-estimation-comparison.md) show known shifts, ambiguity and off-model limits. Its [task pointer](tasks/translation-estimation.md) owns checkpoint/review/check/publication evidence. The owner next requested the roadmap slice stacked above verified PR #14. It prepares inputs for existing separation/reconstruction under stationary integer-bin illumination and a fixed shift-invariant imaging system. Its [task pointer](tasks/integer-drift-correction.md) owns exact evidence. No raw-phase displacement inference, fractional interpolation or camera-motion model is implied.

The owner permits studying legacy algorithms but requires independently written code. `SIMrecon_svn/` remains ignored, unshipped reference material. Do not copy, ship, link or import it. ## Stack and structure

- Python 3.13.12, uv 0.12.19, locked `uv.lock`, one isolated `.venv` per worktree. NumPy/SciPy form the numerical stack; h5py 3.16.0 is runtime and mrcfile 1.5.4 a development reference.
- Owned library/runtime code lives in `src/simrecon/`; owned verification tools live in `scripts/`. Native statement/branch measurement includes both, never-imported files and relevant subprocesses.
- Root [AGENTS.md](../AGENTS.md) holds shared operating rules; four `.agents/skills/` procedures hold role differences; the [delivery specification](agentic-software-delivery-v1.0/DELIVERY-SYSTEM-SPEC.md) defines policy. Root [LESSONS/](../LESSONS/README.md) remains the single append-only lesson home.
- Git and GitHub Actions provide ordinary checks. Prompted role/file restrictions are not engineered access controls. No controller, daemon or scheduled model loop is installed.
