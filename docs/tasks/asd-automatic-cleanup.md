# ASD automatic task-completion cleanup

**Version 1.0.** Delivery-policy documentation amendment. ASD means agentic software delivery.

The owner asked the coordinator to update ASD so it cleans up automatically once a task finishes. This addition accompanies the active 3D translation task; it changes no scientific contract, frozen tests, implementation ownership or gate. The coordinator automatically inventories and cleans positively identified disposable generated fixture repositories and temporary scratch after owned processes close and required evidence is retained and verified, subject to explicit preservation/blocked exceptions.

The sole [Current state](../../artifacts/roadmap-successor-20261018/current-state.md) records policy proposal/review/activation status, candidate pins, checks, cumulative accounting and next action. It is local ignored coordinator evidence; no competing Current state is stored here. Draft candidates and exact patch are in local support packet `artifacts/roadmap-successor-20261018/S02`. Fresh independent policy acceptance is required before activation. This documentation amendment installs no executable cleanup tool, daemon or age-pruner. Any reusable destructive cleanup implementation needs a separate concrete scoped contract, risk classification, named ownership, tests and required independent reviews before use. Actual cleanup/automation retains its existing risk route, named ownership, tests, reviews and gates.

Scope: root AGENTS; specification section 9.1; TASK/HANDOFF templates; narrow intake/worker/reviewer/test-author scope sentences; [completion workflow](../operations/fixture-cleanup.md); this pointer. No runtime, tests, fixtures, scripts, dependencies, coverage or executable workflow change. Existing full-local submission policy remains binding; relevant documentation checks establish only this proposal's consistency.

|---|---|---|

| S6: mutation/verification failure | Stop affected scope, diagnose within ownership, retain charges and renew affected proof. | No hidden retries or invalid evidence reuse. |
| S7: completion report | Report actual removed/trimmed/preserved/blocked scopes, defined counts/native allocated bytes, before/after proof and limits. | No universal custody or task-attributed free-space claim. |
| S8: new cleanup tool/automation | Existing impact/risk classification, ownership, tests/reviews and gates still apply; reusable destructive behavior remains high risk. | No documentation-created execution exemption. |
