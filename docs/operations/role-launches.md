# Native role launches

**Version 1.0** Git versions revisions.

This is coordinator guidance. The launched role performs its packet directly; it does not launch another role. Choose the approved route first: one mechanical worker; bounded worker with named test/infrastructure ownership plus one fresh reviewer; or fresh initial A/B/C/D for high risk. Data-loss behavior, including settled overwrite/truncation repair, requires the high-risk route and never bounded ownership. Policy adoption has its own fresh independent policy reviewer. A/C may continue their own authorized unexposed work; B/D verdicts use fresh native roots; bounded/policy verdicts use fresh independent sessions without author history, with no extra mandatory native launcher for policy review. Do not resume/fork implementation history into review. Use supported memory/delegation controls, one packet/worktree/report destination. Routine fresh role transitions and diagnosed in-scope corrections follow the human request; no default review/repair quota or repeated document approval applies. No silent fallback or uncontrolled automatic retry loop.

Record applicable `command -v codex`, `codex --version` and `codex exec --help` evidence when missing/stale. The observed parser accepts:

```sh
codex exec --ignore-user-config --disable memories --disable multi_agent \
  --sandbox read-only --model <packet-model> \
  -c 'model_reasoning_effort="high"' --json \
  -C /absolute/path/to/worktree -o /absolute/path/to/final.txt \
  - < /absolute/path/to/packet.txt
```

The `-o` destination receives the final assistant message. If the packet asks the role to write a detailed report, use a different path for that report; otherwise the final message can overwrite it.

Select `workspace-write` for authorized A/C, bounded or mechanical authoring; scope still comes from the packet. Required reviewers remain report-only. The high-risk C packet never gains bounded test/infrastructure ownership. `--approve-for-me` already selects workspace-write; do not combine it with explicit `--sandbox`. Set reasoning only with supported native configuration. The observed Codex 0.160.0 parser exposes `-c/--config`; supported effort depends on model/client. The [official configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference) documents `model_reasoning_effort`. [Project model selection](model-selection.md) separates initial conservative choices from calibration candidates. Record actual executable/version, header/model/effort, command, packet revision, worktree, timestamps/status/report; unavailable settings/counters stay unknown. Controlled launcher tests do not establish live role/model behavior.

Use [PUBLIC-PACKET.md](../agentic-software-delivery-v1.0/templates/PUBLIC-PACKET.md) for A/B. B additionally gets A's exact tests/fixtures and sanitized public evidence. Exclude plans, coordinator history, implementation-bearing Current state, coverage maps and LESSONS entries. Use [CANDIDATE-PACKET.md](../agentic-software-delivery-v1.0/templates/CANDIDATE-PACKET.md) for C/D, bounded/mechanical workers and final/policy reviewers; select the explicit mode and named ownership. C gets frozen checkpoint/file identities. High-risk correction packets include sanitized public findings, changed tests and test/requirement dependencies; shared oracle/fixture changes expand fresh B review and unchanged accepted evidence is retained only by reviewer verdict. B/D assess and hand off; they do not repair review targets.

Before blind probes, arrange source-free warning/traceback rendering for Python, pytest and relevant subprocess channels. Retain types/categories, messages, locations and status; suppress source snippets/locals, not diagnostics. Disclose unsupported channels or exposure and stop blind work for coordinator routing. Packets identify the permitted harness/checks.

Use supported bounded terminal waits/notifications with explicit timeout/failure handling; honor any actual human-set total limit. Yield on unchanged status rather than repeated reads; a disconnected launch cannot imply completion. Timeout leaves evidence incomplete and remains a recorded attempt. Diagnose before resuming or retrying within scope, without a default allowance-extension approval. Do not create a reviewer merely as a connectivity probe. A helper, fallback route or host change needs demonstrated scope within the request; missing material decisions, unclear/outside-request objectives or required external authority return to the human. Prompt restrictions are not filesystem isolation. The existing [doctor scope](../tasks/setup-doctor.md) is not a general role coordinator.
